# 存档可靠性修复记录

## 目标与授权
- 2026-09-19：用户要求修复 Android APK 中疑似退出/清后台后进度丢失、恢复点仍在的问题，并检查所有存档相关代码。
- 范围：主存档读写、原生持久化、启动恢复、每日备份、导入/恢复/重置、云存档、存档格式与迁移。允许代码修改及必要检查；不打包、不发布、不提交 Git。
- 保留已有社区、农场、钓鱼、远征、音频及界面修复等未提交改动；不访问或修改真实玩家存档。单助手，无 Computer Use/截图。

## 已确认与决定
- 主存档在 localStorage；Android 每日恢复点在原生 backups 目录。7 种内存故障模拟确认两者可独立失效。
- 启动遇到格式正常的旧主存档会跳过恢复点检查，已用同一存档的 1 级主记录与 20 级恢复点验证。
- 原主存档保存依赖 React effect；写入出错后本次会话暂停保存，但部分操作仍可继续。
- 修复需保留主动导入/重开语义，不能仅按等级或资源多少判定回退；错误时保留原始副本。
- 尚未在 Android 实机复现系统杀进程造成的原始故障；代码/故障注入验证不能代替实机确认。

## 进度与验证
- 已复核工作区 status/diff，原有变更不回退。
- 已完成：启动始终核对恢复点，使用原始保存时间和同一存档 ID 判断回退；正常重复备份、主动导入、不同存档不误报。出现较新进度时暂停自动写入，供玩家选择；也保留当前主存档选项。
- 已完成：启动迁移推迟至恢复检查之后，避免迁移写入的新时间掩盖旧进度；原生备份不可读取或任意平台含未知新版格式时阻止自动覆盖，仍可导出主存档。网页容器禁用可选备份数据库时保持健康主档可用，避免引入 B 站/Web 启动回归。
- 已完成：原生新增 recent.pocpet / recent-previous.pocpet，与每日历史分开；同步临时文件后原子替换，Unix 同步目录，写入串行化。操作触发近期副本，普通时间推进合并为每 5 秒保存，切后台/pagehide 请求立即写入。
- 已完成：操作先写主存档再更新 React 状态；失败暂停后续状态变化，允许重试或导出。抽卡入口接入同一保护，失败不展示抽卡成功结果。已确认导入通过专用入口接纳持久化后的状态。
- 已完成：导入/重开使旧备份任务失效；原生队列合并连续请求、重试失败副本，并在写入前再次核对主存档，防止过期页面写回。
- 已完成：恢复界面导出优先使用本次主存档原文；新增提示支持中文，并在英文缺少条目时回退中文。

## 待人工验证及边界
- Android 真机安装包含本修复的新 APK 后，安排打工/领取奖励，立即切后台并结束进程，再打开检查主档与恢复界面；本任务未打包或进行画面检查。
- 原生近期副本通过异步桥接写入；无法承诺在系统任意指令处强杀时最后一次操作零损失。双副本和启动核对用于避免静默清零，并提供最近可用进度。
- 系统“清除应用数据”会同时删除 WebView 和应用私有文件，需用户另行导出的备份；本修复不改变该系统行为。

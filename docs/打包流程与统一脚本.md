# 打包流程与统一脚本

## 目标与范围

- 用户要求总结现有流程，并提供可选择类型的自动打包脚本。入口为 `scripts/package.mjs`，复用现有平台脚本。
- 脚本开发阶段仅实现入口与必要验证；后续实际打包按下方执行记录授权范围进行。
- 保留已有功能、存档修复、素材和文档改动；打包脚本不会自动暂存、还原或清理这些文件。

## 使用

在项目根目录运行 `npm.cmd run package`，输入编号或类型；逗号分隔可多选，回车选择 Windows x64 + Android arm64，`q` 退出。

```powershell
npm.cmd run package -- --type toy
npm.cmd run package -- --type android
npm.cmd run package -- --type windows,android
npm.cmd run package -- --type full
npm.cmd run package -- --type web
npm.cmd run package -- --type windows-x86,android-armv7
```

预览不会修改版本、备份文件或执行构建：

```powershell
npm.cmd run package -- --type toy --dry-run
node scripts/package.mjs --type windows,android --dry-run --json
npm.cmd run package -- --list
```

非交互调用必须指定 `--type`。类型不合法时直接报错，不回退为全量构建。`--type` 可重复，别名 `full` / `all` / `default` 都只代表本地默认的两种测试包。

| 类型 | 产物 | 复用流程 |
|---|---|---|
| `windows` / `win` | `release/pocket<版本>.exe` | `package:win:portable`，Windows x64 |
| `android` / `apk` | `release/pocket<版本>.apk` | `package:android:arm64`，重建 Rust，已有测试签名 |
| `windows-x86` | `release/pocket<版本>-win32.exe` | `package:win:portable:x86` |
| `android-armv7` | `release/pocket<版本>-32bit.apk` | `package:android:armv7`，重建 Rust，已有测试签名 |
| `toy` / `bilibili` | `release/pocket<版本>-toy.zip` | `build:toy` → `check:toy` → Toy 资源校验 → ZIP |
| `web` | `release/pocket<版本>-web.zip` | `build` → 普通版资源校验 → ZIP |

默认不构建 32 位、Web、Toy、macOS、Linux。macOS/Linux 沿用对应系统或项目 CI；此脚本不在 Windows 上尝试跨系统原生打包。

## 自动执行顺序

1. 读取 `package.json` 版本、Git 提交和工作区状态，展示选择及输出路径。
2. 检查依赖和所选平台环境。Android 自动查找已有 JDK/SDK，并提前验证创建符号链接的权限；不修改系统设置、不自动生成签名密钥、不安装依赖。
3. 以 `package.json` 为准同步 `package-lock.json` 根版本、Tauri、Cargo.toml 与 Cargo.lock 中本项目版本。依赖版本不变。
4. 执行 `npm.cmd run check:release`。校验失败立即停止。
5. 每个目标构建前，将已有同名产物复制到 `release/backups/<时间>-<进程号>/`，比对 SHA-256。只处理选中的产物。
6. 顺序执行所选流程。原有 Windows/Android 脚本核对版本、架构、内嵌资源，Android 还核对 APK 签名和 manifest；ZIP 回读校验入口、版本、edition、Git revision、SDK 和资源清单。
7. 记录最终产物大小与 SHA-256，写入独立的 `release/package-<版本>-<时间>-<进程号>.json`。任一步失败即停止后续目标；进入构建阶段后还会记录失败位置并保留旧包备份。环境或发布前置检查失败时只输出错误，不创建构建记录。

Android 使用已有 debug keystore 对 release 优化 APK 签名，适合本地测试；不等于正式商店签名。默认重建 Rust，避免存档原生修复漏入 APK。若提示符号链接权限不足，应先处理权限，再重试，不要反复运行相同失败构建。

## 源码范围与发布边界

脚本默认打包**当前工作区**，包含已跟踪和未跟踪的功能修改；启动输出及构建记录会明确标记 dirty 状态。要求干净源码时使用 `--require-clean`，有改动即报错。

此前“只包含已提交代码和指定界面修复”的 Toy 包使用了独立 detached worktree，仅复制获准的 CSS 修复。此类精选范围仍应先准备独立工作区，再在该工作区使用脚本；不能从当前包含其他开发内容的工作区直接打包并声称只包含某个修复。若基线尚未包含统一入口，复制 `scripts/package.mjs` 到独立工作区的 `scripts/` 后运行 `node scripts/package.mjs --type toy`，脚本以自身所在项目为根目录。

打包完成不会提交 Git、创建标签、触发 CI、部署 GitHub Pages 或更新 B 站 Toy。Toy 的上传流程仍为：校验包 → 平台检查工具检查 → 预览 → 明确更新授权后提交 → 查询审核状态。上传现有 Toy 时保持原 ID/slug；当前账号和审核状态需要现场查询，不沿用历史记录。

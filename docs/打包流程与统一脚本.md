# 打包流程与统一脚本

## 使用

在项目根目录运行 `npm.cmd run package`。输入编号或类型，逗号分隔可多选；回车默认 Windows x64 + Android arm64，`q` 退出。

```powershell
npm.cmd run package -- --type windows,android --android-signing release
npm.cmd run package -- --type full --android-signing release
npm.cmd run package -- --type toy
npm.cmd run package -- --type windows-x86,android-armv7
```

预览只显示计划，不同步版本、不备份文件、不构建：

```powershell
npm.cmd run package -- --type windows,android --dry-run
node scripts/package.mjs --type toy --dry-run --json
npm.cmd run package -- --list
```

非交互调用必须指定 `--type`。类型不合法时直接报错；可重复传入 `--type`。`full`、`all`、`default` 都只代表默认的 Windows x64 与 Android arm64。

| 类型 | 产物 | 流程 |
|---|---|---|
| `windows` / `win` | `release/pocket<版本>.exe` | `package:win:portable` |
| `android` / `apk` | `release/pocket<版本>.apk` | `package:android:arm64` |
| `windows-x86` | `release/pocket<版本>-win32.exe` | `package:win:portable:x86` |
| `android-armv7` | `release/pocket<版本>-32bit.apk` | `package:android:armv7` |
| `toy` / `bilibili` | `release/pocket<版本>-toy.zip` | `build:toy` → 版本与资源校验 → ZIP |
| `web` | `release/pocket<版本>-web.zip` | `build` → 版本与资源校验 → ZIP |

默认不构建 32 位、Web、Toy、macOS 或 Linux。额外平台仅按明确要求在对应环境构建，GitHub CI 不构建原生包。

## 执行与校验

1. 读取 `package.json` 版本、Git 提交与工作区状态，显示目标和输出位置。
2. 检查所选平台环境；不自动安装依赖、修改系统设置或生成签名密钥。
3. 同步 package-lock、Tauri、Cargo.toml 与 Cargo.lock 的项目版本，保留依赖版本。
4. 执行 `npm.cmd run check:release`，失败立即停止。
5. 将选中目标的同名旧产物复制到 `release/backups/<时间>-<进程号>/`，核对 SHA-256。
6. 顺序构建，校验版本、架构和内嵌资源；Android 另校验 APK 签名与 manifest，ZIP 回读入口、edition、revision、SDK 和资源清单。
7. 将结果、大小与 SHA-256 写入 `release/package-<版本>-<时间>-<进程号>.json`。构建中途失败时保留旧包备份和失败位置。

版本、资源、二进制架构和发布产物集合的校验都集中在 `scripts/check.mjs`：

```powershell
npm.cmd run check:release
node scripts/check.mjs --release --dist dist
node scripts/check.mjs --release --dist dist-toy --edition bilibili
node scripts/check.mjs --artifacts dist-release
```

这些模式供打包和 CI 调用，日常开发使用 `npm.cmd test`。

## Android 签名与环境

Android 默认使用 FrostForge 工作室正式密钥，包括本地测试包。统一入口显式传入 `--android-signing release`，直接调用平台脚本时显式传入 `-Signing release`：

```powershell
npm.cmd run package -- --type windows,android --android-signing release
```

执行前，在本机私密配置或密码管理器中读取以下信息并注入当前进程环境；不要把密码写入命令历史、项目文件或构建日志。

| 环境变量 | 内容 |
|---|---|
| `POCPET_ANDROID_KEYSTORE` | 项目仓库外的正式 keystore 文件路径 |
| `POCPET_ANDROID_KEY_ALIAS` | `android-release` |
| `POCPET_ANDROID_STORE_PASSWORD` | 密钥库密码 |
| `POCPET_ANDROID_KEY_PASSWORD` | 私钥密码；本工作室密钥与密钥库密码相同 |

正式签名缺少配置时直接报错，不回退到 debug。密码通过环境变量交给 keytool/apksigner，不作为明文命令参数。签名密钥和密码只在本机读取，不写入 GitHub Secrets、源码、日志或发布附件。仅在用户明确要求测试签名时使用 `--android-signing debug` 或 `-Signing debug`。

签名前核对证书及 alias，签名后核对 APK 实际证书指纹。签名基准见 `scripts/android-signing-reference.json`：顶层保留固定测试证书，`production` 记录自 2.2.5 启用的正式证书。旧 debug 安装通常无法直接覆盖更新为正式签名版本，需先导出存档，再卸载旧版、安装正式版并导入；后续正式版本继续使用同一证书。构建报告会记录 Android 签名模式。

默认重建 Rust。Windows 缺少创建符号链接权限时，统一入口仅对子进程设置 `POCPET_ANDROID_COPY_NATIVE=1`，使用已有 NDK/Cargo 重编译再复制原生库，随后执行 Gradle 与签名校验。该路径不使用历史原生库，也不修改系统权限。

## 源码范围与发布

脚本打包当前工作区，包含已跟踪和未跟踪的修改；输出与报告标记 dirty 状态。使用 `--require-clean` 可要求干净源码。若只交付部分修改，应先准备对应的独立工作区。

打包本身不提交 Git、不创建标签、不触发 CI、不部署网站或更新 Toy。产物及构建记录不提交 Git。

正式发布先将开发分支合入 `main`，再从干净的同一提交本地构建 Windows x64 与 Android arm64。将这两份产物复制到独立的发布暂存目录，以 `node scripts/check.mjs --artifacts <暂存目录>` 核验附件集合；确认构建报告中的版本、提交、正式签名、大小和 SHA-256 后，推送分支与 `v<版本>` 标签。

通过 `gh release create` 创建草稿，仅附加 `release/pocket<版本>.exe` 和 `release/pocket<版本>.apk`，使用 `--verify-tag` 和 `--notes-file` 指定已推送标签与更新说明。两份附件上传完成后，再用 `gh release edit v<版本> --draft=false --latest` 公开。Release 不附加 Web、Toy、额外架构、更新清单或校验报告；客户端仍能按版本化 EXE/APK 文件名检查和下载更新。

分支／标签推送及手动 CI 只检查代码、存档、版本和前端，不创建 Release，不接触正式签名密钥。公开 Release 后，工作流会从 `main` 调用 `pages.yml`，以 `source=release` 核对已发布标签、提交和两份附件，然后从相同提交构建并部署普通网页；无需下载原生构建产物。独立部署可用 `source=main`，同时指定版本和完整提交号。

Toy 使用 `npm.cmd run package -- --type toy --require-clean` 生成更新 ZIP，再通过 Toy CLI 更新已有作品，沿用作品 ID 和地址；平台审核状态单独反馈。发布规则见根目录 [AGENTS.md](../AGENTS.md)，CI 入口见 [release.yml](../.github/workflows/release.yml) 与 [pages.yml](../.github/workflows/pages.yml)。

# 打包流程与统一脚本

## 使用

在项目根目录运行 `npm.cmd run package`。输入编号或类型，逗号分隔可多选；回车默认 Windows x64 + Android arm64，`q` 退出。

```powershell
npm.cmd run package -- --type windows,android
npm.cmd run package -- --type full
npm.cmd run package -- --type toy
npm.cmd run package -- --type windows-x86,android-armv7
```

预览只显示计划，不同步版本、不备份文件、不构建：

```powershell
npm.cmd run package -- --type windows,android --dry-run
node scripts/package.mjs --type toy --dry-run --json
npm.cmd run package -- --list
```

非交互调用必须指定 `--type`。类型不合法时直接报错；可重复传入 `--type`。`full`、`all`、`default` 都只代表默认的 Windows x64 与 Android arm64。

| 类型 | 产物 | 流程 |
|---|---|---|
| `windows` / `win` | `release/pocket<版本>.exe` | `package:win:portable` |
| `android` / `apk` | `release/pocket<版本>.apk` | `package:android:arm64` |
| `windows-x86` | `release/pocket<版本>-win32.exe` | `package:win:portable:x86` |
| `android-armv7` | `release/pocket<版本>-32bit.apk` | `package:android:armv7` |
| `toy` / `bilibili` | `release/pocket<版本>-toy.zip` | `build:toy` → 版本与资源校验 → ZIP |
| `web` | `release/pocket<版本>-web.zip` | `build` → 版本与资源校验 → ZIP |

默认不构建 32 位、Web、Toy、macOS 或 Linux。macOS/Linux 使用对应系统或 CI runner。

## 执行与校验

1. 读取 `package.json` 版本、Git 提交与工作区状态，显示目标和输出位置。
2. 检查所选平台环境；不自动安装依赖、修改系统设置或生成签名密钥。
3. 同步 package-lock、Tauri、Cargo.toml 与 Cargo.lock 的项目版本，保留依赖版本。
4. 执行 `npm.cmd run check:release`，失败立即停止。
5. 将选中目标的同名旧产物复制到 `release/backups/<时间>-<进程号>/`，核对 SHA-256。
6. 顺序构建，校验版本、架构和内嵌资源；Android 另校验 APK 签名与 manifest，ZIP 回读入口、edition、revision、SDK 和资源清单。
7. 将结果、大小与 SHA-256 写入 `release/package-<版本>-<时间>-<进程号>.json`。构建中途失败时保留旧包备份和失败位置。

版本、资源、二进制架构和发布产物集合的校验都集中在 `scripts/check.mjs`：

```powershell
npm.cmd run check:release
node scripts/check.mjs --release --dist dist
node scripts/check.mjs --release --dist dist-toy --edition bilibili
node scripts/check.mjs --artifacts dist-release
```

这些模式供打包和 CI 调用，日常开发使用 `npm.cmd test`。

## Android 签名与环境

Android 测试包使用已有 debug keystore 对 release 优化 APK 签名。CI 使用固定测试密钥，保持更新安装的签名连续性；正式商店签名另行配置。签名基准见 `scripts/android-signing-reference.json`。

默认重建 Rust。Windows 缺少创建符号链接权限时，统一入口仅对子进程设置 `POCPET_ANDROID_COPY_NATIVE=1`，使用已有 NDK/Cargo 重编译再复制原生库，随后执行 Gradle 与签名校验。该路径不使用历史原生库，也不修改系统权限。

## 源码范围与发布

脚本打包当前工作区，包含已跟踪和未跟踪的修改；输出与报告标记 dirty 状态。使用 `--require-clean` 可要求干净源码。若只交付部分修改，应先准备对应的独立工作区。

打包本身不提交 Git、不创建标签、不触发 CI、不部署网站或更新 Toy。产物及构建记录不提交 Git。发布规则见根目录 [AGENTS.md](../AGENTS.md)，CI 入口见 [release.yml](../.github/workflows/release.yml) 与 [pages.yml](../.github/workflows/pages.yml)。

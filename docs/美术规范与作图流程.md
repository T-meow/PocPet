# 美术规范与作图流程

## 风格与角色

道具采用顺滑卡通风格：深巧克力或紫褐色轮廓、奶油色调、圆润比例，轻微俯视的四分之三视角，左上方光源。使用清楚的色块与少量柔和渐变，保留识别物体所需的细节，避免写实、塑料感 3D、过重纹理或过度扁平。

- 图标缩小到 48px 仍需易认，轮廓与视觉重心保持一致，不添加文字、水印或品牌。
- 云朵可带表情和腮红；金苹果可加少量星光，高价值料理可加少量暖色四角星。
- 非杯装成品料理统一使用奶油色浅盘；杯装饮品保留杯子，不额外套盘。
- 烤鱼加入少量蔬菜、柠檬等配菜和酱汁，表现烤色、刀花与熟肉质感，整体仍以鱼为主。固定鱼汤按食谱表现熟鱼肉块、配料和有颜色的汤底，避免整条鱼孤零零漂在清水中的造型。摆盘点缀不改变游戏配方。
- 猪蹄为圆润整块侧面造型，短骨朝右上；避免圆形切面、同心肉圈或尖锐突起。道具 ID 仍为 `pig_trotter`。
- Furo 新图保持白色身体和脚部，造型简洁可爱；候选图须确认后才能替换正式素材。

## 生成与确认

默认模型为 `gpt-image-2.5-sunburst`，`quality: "medium"`；用户指定优先。正式调用与 dry_run 参数一致，不改写历史请求的质量记录。使用生成工具时读取对应 skill，授权以当前任务和会话上下文为准。

普通商店道具默认使用文字提示，不额外上传角色或参考图；当前任务明确要求参考时再附带。对照模型时保持同一提示词。凭据只从环境或配置读取，不写入日志。

先展示生成原图，用户确认后再切图或接入。通常每批不超过三张，实际数量服从用户要求。画面检查、截图、Computer Use 由用户明确授权；默认由用户人工验收。

## 图集尺寸

| 项目 | 约定 |
|---|---|
| 请求画幅 | 1K、1:1、4×4，共 16 格 |
| 名义单格 | 256×256，中心坐标为 128、384、640、896 |
| 主体范围 | 最长边约 168–184px，安全范围不超过 192px |
| 格内留白 | 四边约 32px，物体与装饰不跨格 |
| 交付图标 | 256×256 透明 PNG；运行时版本通常为 128×128 |

请求尺寸与实际返回尺寸可能不同，处理前读取真实像素尺寸，不能把 1280px 原图记作 1024px。

## 切图与透明处理

1. 按实际尺寸定位格间空白，不直接假定等分线就是切割边界。
2. 用 `alpha > 0 && min(R,G,B) < 220` 判断主体占用，在名义切线两侧约 5% 范围寻找至少 4px 的空白走廊。
3. 去白仅处理与图片边缘相连的背景：`min(R,G,B) >= 238` 且通道差不超过 24，使用四邻域连通，保留物体内部白色。
4. 按主体边界裁切，等比缩放并居中放入 256px 画布，主体最长边约 184px；核对星光、描边与透明边缘不被截断。
5. 普通图标用 Lanczos3 缩放；像素风使用最近邻。运行时可用高质量 WebP，需保留透明交付或 Mod/CG 源图时使用 PNG，避免反复有损压缩。

角色 Mod 不套用上述道具图标的 256px／128px 缩小规格，保留源分辨率并输出无损 RGBA PNG。已有手工透明图时不重复去白，不覆盖用户源图；优先通过整数平移和调整透明留白对齐，完整保留半透明边缘。几何居中后仍由用户检查角色视觉重心和动作大小，具体步骤见[角色 Mod 制作指南](Mod制作指南.md)。

## 文件与代码接入

原图、请求参数和处理清单放在 `output/imagegen/<主题或日期>/`，不把批次日志、生成记录或未来素材计划放入 `docs/`。正式素材进入 `src/assets/`，注册时沿用已有 ID。

### App 图标

收录的图标原图位于 `src/assets/branding/`，均为 1024×1024 PNG，由 mxai 的 `gpt-image-2.5-sunburst` 以 `quality: "medium"` 生成，无宠物形象。

| 素材 | 用途 |
|---|---|
| `app-icon-forest-outpost.png`（F，林间驿站） | 正式 App 图标源图 |
| `app-icon-starlit-camp.png`（C，星夜营地） | 保留备选原图 |
| `app-icon-android.svg` | 引用正式原图，在 Android 自适应图标的 108dp 画布中居中放入 72dp 前景，预留系统裁切空间 |
| `app-icon.json` | Tauri 图标生成配置，背景色取正式原图边角色 |

使用 `npm.cmd run tauri -- icon src/assets/branding/app-icon.json` 更新平台图标。现有 Android 工程会使 Tauri 直接将启动图标写入 `src-tauri/gen/android/app/src/main/res/`；生成后将其中的 `mipmap-*/ic_launcher*.png`、`mipmap-anydpi-v26/ic_launcher.xml` 和 `values/ic_launcher_background.xml` 同步回 `src-tauri/icons/android/`，不要用旧副本覆盖工程。桌面及 iOS 图标位于 `src-tauri/icons/`；网页入口使用 `public/favicon.ico`（复制生成的 `icon.ico`）和 `public/apple-touch-icon.png`（复制 180×180 的 `ios/AppIcon-60x60@3x.png`）。保留完整方形源图，由平台处理图标形状，不按道具图集规则去白或裁切。

### 游戏内资源

常用资源入口：

- `src/assets.ts`：通用道具与宠物资源。
- `src/companionActivityAssets.ts`：伙伴活动资源。
- `src/communityProjectAssets.ts`：聚餐、展览、星空之夜的通用场景 CG；三个场景均无固定主角，各主题与伙伴共用，运行时为 1920×1080 WebP。
- `src/communityFacilityAssets.ts`：社区设施透明图标；地图和生产场景继续用 SVG 绘制背景与动态状态。
- `src/adventureLandmarkAssets.ts`：五个探索地区共 40 张地点、建筑与营地透明图；地图与探索途中共用，途中独立叠加地标和伙伴。地区地形、水面及地图路线继续使用 SVG，不再用建筑简画替代正式地标。
- `src/kitchenEquipmentAssets.ts`、`src/kitchenSceneAssets.ts`：厨具与厨房场景。
- `src/trophyAssets.ts`、`src/miniGameAssets.ts`：奖杯与小游戏。
- `src/museumAssets.ts`：mxai 生成并确认的 36 张纪念馆正式 WebP，位于 `src/assets/museum/`；包含大厅及五展厅场景 6 张、建设与委托展品 20 张、奖杯部件 6 张、编号徽章 2 张、纪念边框 2 张。五件地区珍宝复用现有图标，不另生成。场景无固定主角，运行时叠加当前伙伴与邻居立绘；奖杯与铭牌按解锁等级组合。原始生成文件与请求记录留在 `output/imagegen/`。

扭蛋音效位于 `src/assets/audio/gacha/`：`gacha_spin.wav`、`gacha_drop.wav`、`gacha_reveal.wav`、`gacha_jackpot.wav` 分别用于转动、落球、普通揭晓和高稀有度揭晓。四段声音由项目内程序合成，无外部采样素材，采用 44.1 kHz、单声道、16 位 PCM WAV；在 `src/core/audio.ts` 注册并服从游戏声音开关。

预览沿用正式游戏的 `http://127.0.0.1:5173` 入口，不额外维护独立 HTML 预览。用户在实际布局中确认尺寸、对比度、透明边缘与窄屏效果后完成视觉验收。

## 厨房流程

厨房页提供食谱本、研究搭配与厨具入口，主区域展示伙伴和制作台。食谱详情明确列出材料需求、成品作用、制作份数和本次可得心心；缺少材料时可以打开现有商店补齐。

- 已知食谱：选配方和数量 -> 预览 -> 确认制作 -> 制作演出或可选操作 -> 查看成品 -> 收入背包或喂食。
- 研究：选 1-3 种食材与做法 -> 查看线索与有效组合 -> 确认制作 -> 记录发现。无对应配方时保留食材。
- 厨具：拌制和平底锅起步可用；制作若干不同基础菜后，可用金币购买搅拌机与烤箱。条件与价格放在配置表。
- 试吃：通过现有喂食路径消费成品，再记录该角色第一次吃过这道菜的反应；收藏留言可以在食谱详情回看。

制作确认时校验配方、厨具、材料、数量和伙伴状态，一次扣除成本并生成成品、心心与制作记录，保存后播放演出。退出演出保留已经制作好的料理，可选搅拌、火候和摆盘只补充表现或作品，不再次发奖。这样直接制作与手动参与具有相同基础收益，也无需增加实时烹饪队列。

批量数量必须是正整数，并受实际材料约束。研究输入按明确的食材 ID、数量和做法匹配，标签只提供提示；不能因为 Mod 改了食材名字就匹配到另一道菜。同一次制作请求重复提交，只使用一次操作标识结算。

| 水果蛋奶布丁 | 鸡蛋 + AD 钙奶 + 苹果或香蕉 | 烤箱 | 蛋奶甜点与口味收藏 |
| 苹果烤派 | 苹果 + 面粉 + AD 钙奶 | 烤箱 | 主题下午茶与摆盘 |

水果变体分别有成品图与表现，但按同一基础配方计数。“八味手册”仍使用表中前八道固定配方，完整食谱本显示全部十二道的发现情况。先用双果沙拉与蛋炒饭完成数据和界面，再扩齐其余内容。

配方定义至少包含稳定 ID、材料数量、可接受的水果变体、做法、成品 ID、恢复效果、解锁条件、首做经验、角色反馈与表现素材键。成品使用 `dish_` 前缀的内置物品 ID，加入正式物品注册；成品不在商店直接出售，首发也不提供卖出料理换金币。

## 三类短互动

玩耍页展示三种玩法、玩法记录和已解锁外观。默认适合手机单指操作，桌面支持鼠标和键盘。当前建议免费开始与重玩，金币用于永久玩具和外观选择，具体购买内容继续配置。

| 玩法 | 第一版操作 | 正常完成条件与记录 | 伙伴反馈 |
| --- | --- | --- | --- |
| 接球 | 伙伴抛球，玩家在时机范围内点击接回；提供降速辅助 | 一轮约 30-45 秒，走完有限次数的抛接即完成；记录连续接住次数与所用模式 | 抛出、接住、没接住、庆祝、鼓励 |
| 翻牌 | 默认 3×4 牌阵，点击配对，提供不限时辅助 | 找齐六对即完成；记录步数、用时与模式；后续开放更多牌面 | 观察、提示、找到一对、完成 |
| 吹泡泡 | 按住吹大、松开飘走，点击或让伙伴追着戳破 | 自由结束；奖励根据实际有效互动定义，候选为累计约 30 秒参与且完成数次吹泡泡；记录特殊形状 | 看泡泡、追逐、戳破、惊喜 |

最终局长和奖励条件在可玩版本中校准。基础奖励不要求达到高分；速度、正确率用于玩法记录和表现收藏。练习与正常完成的计数在模式配置中明确，不能仅通过进入页面、停在后台或立刻退出领取完成奖励。

基础翻牌直接开放；玩具球首次实际使用后永久开放接球，老档中已持有或有明确使用记录的玩家也可解锁；泡泡棒购买一次永久使用。泡泡棒放在玩法装备状态中，不反复消耗；旧玩具球原有恢复用途继续保留。

一局开始时记录参与角色、模式、随机局面和奖励依据。帧动画、指针坐标和粒子放在组件内，匹配结果、抛接轮数等关键进度才进入状态快照。切后台暂停主动游戏计时，返回可以继续或结束；伙伴改去日程、睡眠或状态不适合继续时明确结束或暂停，不在后台自动完成一局。完成时合并记录、奖励和记忆并清除活动标记，重复结束无第二份奖励。

## 必要状态与模块

先新增三个领域模块，不提前制作通用剧情编辑器或另一套存档系统：

| 拟新增位置 | 职责与主要函数 |
| --- | --- |
| `src/core/kitchen.ts` | 配方与厨具配置、默认与归一化状态、研究预览、`craftRecipe`、首做与试吃登记 |
| `src/core/miniGames.ts` | 玩法配置、默认与归一化状态、开始/暂停/继续/完成、记录和外观解锁 |
| `src/core/companionMemories.ts` | 记录有意义的共同经历、挑选相关回忆、推进少量固定后续 |
| `src/ui/KitchenPage.tsx`、`src/ui/app/useKitchenController.ts` | 厨房展示、选择和提交动作，调用核心规则 |
| `src/ui/PlayPage.tsx`、`src/ui/app/usePlayController.ts` | 玩法入口、局内生命周期与结果展示 |
| `src/ui/play/` 下的三个玩法组件 | 各自的输入、局面与动画，调用统一的本局开始和完成接口 |

`PetState` 增加 `kitchen`、`miniGames`、`companionMemories` 三个字段，各自有默认值和小版本号，建议保存下列必要信息：

- 厨房：已发现配方、厨具解锁、各配方制作次数与首做时间、各角色首次试吃记录、最近制作操作标识；合计进度尽量由这些数据计算。
- 短互动：永久玩法与外观解锁、各模式最佳记录和完成次数、当前局的稳定标识与可恢复进度、开始时的参与角色与奖励依据。
- 记忆：有意义事件的 ID、参与者、地点、相关配方或作品、选择与结果、发生及最近提及时间，以及当前可继续的小目标。重复经历合并计数，关键回忆与收藏保留。

新物品加入 `BuiltinItemId`、`shopItems`/`specialItems` 和图片映射。基础生食材标为不可直接使用，配方成品可喂食；厨具和永久玩具使用专门购买动作写入解锁状态。现有未知物品与 Mod 回退继续工作，配方研究首版只识别明确配置的食材。

新字段在 `createDefaultPet`、`normalizePet` 中补齐，旧档没有制作记录时从零开始。存档外层版本不因增加可选领域字段而随意重做；按现有备份格式导出导入，并在需要移动运行时间时接入 `gameClock`。已经发生的回忆日期和正在进行的活动计时分别处理。

## 基础记忆先做三条完整后续

| 起点 | 之后怎样提起 | 可自愿继续的事与成果 |
| --- | --- | --- |
| 第一次做出并喂食蛋炒饭 | 伙伴在厨房提起那顿饭 | 再做一道不同正餐，留下第一张菜单页 |
| 第一次完成水果松饼试吃 | 伙伴看见另一种水果时提起上次口味 | 尝试另一已配置变体，留下对照的食谱照片 |
| 接球刷新一次个人记录 | 下一次打开玩耍页时伙伴做出接球动作 | 再一起玩一局，无需打破纪录，留下共同练习的合影 |

这些是可配置的内容样例，使用当前伙伴的稳定角色 ID。首次试吃记录与回忆相互引用，不给同一事件重复发奖。对白只描述真实发生过的事，当前只主动展示一个可继续目标，允许以后再做。冒险版本再加入邻居和基地场景，不在此次先行版本里实现旅行入口。

## 收益与兼容

一年目标的每份料理、每局短互动基础 12 心继续作为预算候选，按开始时已有等级倍率计算，之后沿用现有成就和增益卡追加方式。厨房一次批量制作按实际份数逐份执行相同奖励规则；小游戏一局只执行一次。食谱首做经验、固定成就奖励与普通产心分别有明确归属，回看动画或回忆不再发奖。

成品喂食继续走现有食物效果与喜好处理，料理技能和奖杯加成只应用一次。首做料理经验复用料理技能的升级逻辑，但不增加日程完成次数或大师次数。

当前旧物品收集目标由商店列表派生，增加可用物品前要固定已发布的旧清单；“任务大师”的旧普通成就集合也保持原目标。厨房的六项候选成就可直接用制作与试吃记录派生，短互动的首次完成和成绩收藏随后配置，避免另外堆一套重复统计。

还需在玩法实现期间定下两个经济选择：厨房批量制作是否持续按份产心，以及短互动是否取消原每日奖励次数。它们不妨碍先完成配方、游戏和存档流程，但必须在最终收益配置与经济验收前收敛。现有日收入 500 心只是测算条件，不能直接承诺所有玩家 366 天满级；厨房先行阶段的成长也单独检查。

## 画面与资源安排

厨房采用制作台与伙伴场景，桌面在侧边展示食谱详情，手机将材料、数量和操作放在场景下方。玩耍进入独立场景，主要操作区避开系统返回与底部手势区域，重要反馈同时提供画面与文字。

按素材充足安排每道料理的成品、变体、研究提示和制作过程；三个角色分别配置递食材、制作、试吃、接球和泡泡反应，并准备厨具、卡背、球外观、合影等收藏。局内动作通过各玩法自己的资源表选择，首页状态继续使用现有 `PetStatus`/`RecentActivity` 表示生活状态。

存档保存作品参数和素材 ID，图片资源随应用或资源包管理，不把整张图片重复塞入每条回忆。只加载当前场景所需资源，手机性能按同时显示的内容控制。角色缺少某一动作时使用该角色的基础反馈图，未知 Mod 仍可以完成基础操作。

## 开发顺序与验收

| 步骤 | 交付内容 | 完成标志 |
| --- | --- | --- |
| 1. 数据与兼容 | 新状态、物品、配方配置及旧目标固定清单 | 旧档能正常读取，新料理能作为已知物品保存 |
| 2. 厨房完整流程 | 双果沙拉、蛋炒饭、研究预览、直接/批量制作、喂食与首做记录 | 买材料到看到试吃反馈完整可用 |
| 3. 第一种短互动 | 翻牌、开始与暂停恢复、结束结算及玩法记录 | 一局可以完成，反复结束不重复奖励 |
| 4. 扩齐内容 | 十二道配方、厨具、可选制作表现、接球和吹泡泡 | 三类互动和全部基础做法独立可用 |
| 5. 记忆与收藏 | 三条后续、厨房成就、食谱留言及玩法收藏 | 真实经历在以后出现对应反馈 |
| 6. 收益与端侧检查 | 定下重复收益规则，校准数值和手机布局 | 功能与成长节奏可供用户体验验收 |

第一轮实现从步骤 1 和 2 开始，以“购买鸡蛋和大米 -> 制作蛋炒饭 -> 喂食 -> 留下首次试吃记录”为最小完整交付。地图规划保持在文档中，不与这段实现混做。

实现后优先用数据检查关键情况：材料不足和无效组合不扣除、批量与逐份结算一致、正常喂食确实消费、重复提交不重复发奖、旧档与导入不丢新字段、角色切换不改写已发生的经历。小游戏再检查后台暂停和重复结束。复用现有检查风格，必要时集中到一个小的检查脚本，不逐配方复制测试。

完成变更后运行一次对应数据检查及 `npm.cmd run build`，再验收主要页面的手机/桌面交互与中文显示；只有数据难以确认的画面表现才额外做视觉检查。玩法实质验证完成后提醒提交 Git，本轮不提交。
